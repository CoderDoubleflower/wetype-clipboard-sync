# WeType Clipboard Sync 0.5.0 · Windows 使用说明

本程序通过手机微信输入法的「跨设备粘贴」，双向同步手机与 Windows 电脑的**文本和图片剪贴板**。支持 **Windows 10 1607 及以上 / Windows 11**；发布包中的 **x86 是 32 位程序**，可在 64 位 Windows 上兼容运行。

## 安装与首次配对

从 [项目 Releases](https://github.com/CoderDoubleflower/wetype-clipboard-sync/releases) 下载以下一种包：

| 文件 | 使用方式 |
| --- | --- |
| `wetype-clipboard-sync-0.5.0-windows-x86-setup.exe` | 运行安装向导，安装到当前用户，不需要管理员权限 |
| `wetype-clipboard-sync-0.5.0-windows-x86-portable.zip` | 完整解压到固定目录，再双击 `wxclipd-background.exe` |

安装版默认位置为 `%LOCALAPPDATA%\Programs\WeTypeClipboardSync`。安装时的 **Start clipboard sync when I sign in** 控制登录后自启；完成后启动程序，右下角出现微信输入法图标。右键图标打开「设置与配对」，也可以使用开始菜单中的 **Setup and Pair**。本项目是非官方同步工具，状态窗口标题为 **WeType 剪贴板同步 — 状态与配置**。

设置向导依次询问：

1. **代理地址**：首次使用默认直连。回车保留当前设置，输入 `direct` 改为直连，也可输入下文列出的代理 URL。
2. **远端轮询秒数**：回车使用当前值，Windows 默认 10 秒，可设为 1～3600 秒。
3. **设备名称**：首次创建身份时询问，回车使用电脑名称。
4. **手机配对码**：在手机微信输入法中打开「跨设备粘贴」，把手机显示的六位码填入窗口，并在手机端确认。已有配对时可回车跳过。

完成后程序启动后台同步，按 Enter 关闭设置窗口即可。重新打开设置向导时，会先停止正在运行的同步进程，保存设置后再启动。

首次使用先在电脑和手机分别复制一段新文本验证，然后按下文操作验证图片。手机复制到电脑的默认主动拉取间隔是 10 秒，实际时间还取决于网络和代理。**按下 Ctrl+V 本身不保证远端内容已经到达。**

Windows 版本尚未使用真实手机账号完成端到端实测，需要在你的手机、代理和桌面会话中验证首次配对及双向同步。

### 从 0.2.x / 0.3.x / 0.4.x 升级

运行 0.5.0 安装包覆盖安装，安装器会停止旧版进程。配对身份和代理配置保存在状态目录中，升级会保留它们；已有配对无需重新绑定。便携版先停止同步并退出托盘，再完整解压新版覆盖程序文件。

## 托盘、状态与配置

双击右下角微信输入法图标，打开状态与配置窗口；右键图标打开操作菜单。如果任务栏没有直接显示图标，请展开 `^` 隐藏图标区域，也可以从开始菜单再次打开程序。重复启动会定位已有托盘，不会再启动一套同步进程。Windows 资源管理器重启后，程序会重新登记图标。

状态窗口使用 WPF，提供状态概览、收发统计、运行信息与配置分组，支持窗口缩放、高 DPI 与键盘操作。安装包已经包含 x86 .NET 桌面运行时，无需另外安装。

**自动主题：** 在 Windows「设置 → 个性化 → 颜色」修改应用模式，窗口内容、控件及支持的系统标题栏会即时适应深色 / 浅色。若 Windows 分别设置系统与应用模式，以**应用模式**为准；不需要关闭窗口或重启同步。高对比度开启时使用系统高对比度颜色。

状态窗口定期刷新，提供：

- **运行情况**：初始化、运行、连接重试或已停止，最近一次错误提示。
- **当前实际配置**：代理类型与地址（隐藏用户名、密码）、代理来源、远端轮询间隔、本地检查间隔、粘贴触发开关。
- **同步记录**：本次运行的发送 / 接收次数和最近时间、待发送与发送结果不确定的提示。它不展示剪贴板内容，也不是跨重启的历史记录。
- **本机信息**：设备名、版本、状态目录，以及磁盘中保存的配置。保存的配置与运行配置可能不同，修改后用「重启同步」应用。

状态读取使用本地控制通道，不会为了刷新窗口额外请求微信服务。网络或代理不可用时仍可查看与停止；“运行中”表示同步循环已启动，最近成功时间才说明何时有操作成功，不能把进程存在等同于持续在线。

| 托盘操作 | 作用 |
| --- | --- |
| 状态与配置 | 打开或定位状态窗口 |
| 开始同步 | 使用当前设置启动后台同步 |
| 停止同步 | 停止收发，保留托盘入口 |
| 重启同步 | 重新加载配置并启动同步 |
| 立即同步 | 请求检查本地剪贴板并提前拉取远端 |
| 设置与配对 | 打开现有控制台向导，修改代理、轮询间隔或完成手机配对 |
| 查看日志 / 打开配置目录 | 打开当前状态目录的日志或文件夹 |
| 退出 | 停止同步并退出托盘 |

关闭状态窗口只隐藏窗口，程序继续在托盘运行。「设置与配对」期间会停止同步；向导完成后恢复。向导最后显示「按 Enter 关闭窗口」时请按 Enter 结束；设置窗口仍在时，退出或升级会提示先关闭它，避免未结束的向导在退出后重新启动程序。保存后仍受真正设置的 `WXCLIPD_PROXY` 环境变量影响时，可在状态中的代理来源辨认。

## 图片怎么同步

**电脑 → 手机：** 使用 Windows 截图工具截取并复制，或在浏览器、图片编辑器中选择「复制图片」。等待同步，在手机支持图片粘贴的输入框或应用中粘贴。图片若同时附带文字地址，程序优先读取图片。

**手机 → 电脑：** 在手机应用中复制图片，等待同步后，在 Windows 画图、图片编辑器或支持图片的聊天窗口中按 Ctrl+V。接收的图片会写入 Windows 原生位图剪贴板；PNG 同时保留 PNG 剪贴板格式。是否能从某个手机应用复制、粘贴图片，还取决于该应用和官方微信输入法的支持。

在资源管理器中选中 `.png` / `.jpg` 文件再按 Ctrl+C，复制的是文件对象（`CF_HDROP`），本版不上传这种对象；请打开图片后使用「复制图片」。

### 格式与大小

- 读取 Windows 注册的 PNG、`CF_DIBV5`、`CF_DIB`；传输与接收解码支持 PNG / JPEG。
- 编码后最多 **16 MiB**；解码后最多 **16,777,216 像素**（64 MiB RGBA），每边最多 **16,384 像素**。服务端动态返回的上传限制仍会生效。这是本客户端的保护边界，不代表所有手机或服务端都有同样上限。
- 原始 JPEG 尽量直接保留。位图优先转 PNG，超过 16 MiB 时仅对完全不透明的图片尝试 JPEG 质量 95、90 的**有损压缩**，不缩小尺寸。透明图片超限会记录错误，不会自动丢弃透明度。
- 不支持任意文件传输、富文本格式保留或动图播放；不将 GIF / WebP 等编码作为接收格式。

图片下载期间仍会检测本地复制；新复制的文本或图片优先。剪贴板被占用时会重试，写入成功才确认接收；收到的图片不会自动反向上传。确定损坏、格式不支持或超限的远端图片会记录原因并跳过，后续内容仍可继续同步。

## 日常启动、停止与日志

安装版开始菜单中的 **WeType Clipboard Sync** 提供：

| 入口 | 作用 |
| --- | --- |
| **WeType Clipboard Sync** | 打开托盘与状态窗口 |
| **Setup and Pair** | 修改代理、轮询间隔并完成配对 |
| **Start Sync** | 启动托盘及后台同步 |
| **Stop Sync** | 停止后台同步 |
| **Sync Now** | 请求正在运行的进程尽快同步一次 |
| **Windows Guide** | 打开本说明 |
| **Uninstall** | 卸载程序 |

便携版双击 `wxclipd-background.exe` 启动托盘；双击 `wxclipd.exe` 仍可进入设置向导。**保留这两个文件及完整的 `ui/` 子目录，不要只复制 EXE**。`ui/` 包含 WPF 窗口和随附运行时；直接启动入口仍是 `wxclipd-background.exe`。便携包不自动登记登录自启。

也可以在程序目录打开 PowerShell，运行：

```powershell
.\wxclipd.exe start
.\wxclipd.exe inspect
.\wxclipd.exe status
.\wxclipd.exe sync-now
.\wxclipd.exe stop
.\wxclipd-background.exe --quit
```

默认日志位于 `%LOCALAPPDATA%\wxclipd\wxclipd.log`。查看最近日志并持续跟踪：

```powershell
Get-Content "$env:LOCALAPPDATA\wxclipd\wxclipd.log" -Tail 50 -Wait
```

`start` 返回表示请求启动托盘与后台进程，网络初始化仍可能在重试；有问题时查看状态窗口及日志。`inspect` 返回本地运行快照 JSON，即使配置文件损坏也可查询已有进程；`status` 继续查看远端剪贴板状态。`stop` 保留托盘，`wxclipd-background.exe --quit` 才会同时停止同步并退出托盘。`sync-now` 返回只表示同步请求已受理，并不是本轮收发完成的确认。

前台排错时先停止后台进程，再运行：

```powershell
.\wxclipd.exe stop
.\wxclipd.exe run
```

前台按 Ctrl+C 退出，需要恢复后台时再执行 `.\wxclipd.exe start`。

## HTTP / SOCKS5 代理

推荐通过 **Setup and Pair** 填写代理，或者使用 `config` 命令保存：

| 地址示例 | 行为 |
| --- | --- |
| `http://127.0.0.1:7890` | HTTP 代理；HTTPS 和 WSS 使用 CONNECT 隧道 |
| `socks5://127.0.0.1:1080` | SOCKS5，由本机解析目标域名 |
| `socks5h://127.0.0.1:1080` | SOCKS5，由代理解析目标域名 |
| `http://user:password@127.0.0.1:7890` | 带 HTTP Basic 用户名密码认证 |
| `socks5h://user:password@127.0.0.1:1080` | 带 SOCKS5 用户名密码认证 |

端口应填写你的代理软件实际监听端口。用户名或密码中的 `@`、`%` 等保留字符需要 URL 百分号编码，例如密码 `p@ss` 应写为 `p%40ss`。`socks5h` 仅将目标域名交给代理解析，代理服务器自身的域名仍需本机可解析。

例如，保存 SOCKS5h 代理并应用：

```powershell
.\wxclipd.exe --proxy "socks5h://127.0.0.1:1080" config
.\wxclipd.exe stop
.\wxclipd.exe start
```

恢复直连：

```powershell
.\wxclipd.exe --no-proxy config
.\wxclipd.exe stop
.\wxclipd.exe start
```

托盘窗口显示运行进程实际使用的配置。`.\wxclipd.exe config` 查看下一次命令将解析到的配置；两者在修改文件后、重启前可能不同。显示时会隐藏用户名密码，但保存的代理 URL 保留原始凭据。

配置优先级是 **命令行 `--proxy` / `--no-proxy` > 环境变量 `WXCLIPD_PROXY` > `config.json` > 直连**。空的 `WXCLIPD_PROXY` 表示直连；若该变量仍存在，它会覆盖文件内的代理。普通临时命令不会更改已运行的后台进程，**保存后需要 `stop` 再 `start`**。

程序忽略 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY`、`NO_PROXY` 和 Windows 系统代理自动配置。代理统一用于 Session 登录 / 配对请求、COS 图片与较长文本上传 / 下载、WSS 通知连接；代理不可用或认证失败时不会自动改为直连。暂不支持 PAC、`https://` 代理端点和 NTLM / Kerberos 等企业代理认证。

## 配置文件与状态目录

默认状态目录是 `%LOCALAPPDATA%\wxclipd`。可把此路径粘贴到资源管理器地址栏打开。配置文件为其中的 `config.json`，Windows 默认内容为：

```json
{
  "proxy": null,
  "poll_interval_seconds": 10,
  "paste_trigger": true
}
```

`proxy` 为 `null` 表示直连，也可改成代理 URL 字符串。直接编辑时必须使用有效 JSON，保存后重启同步进程。包内的 `config.example.json` 只是示例，放在程序旁边不会自动生效。

通常使用命令更方便，例如把远端轮询改成 15 秒、关闭 Ctrl / 右键触发：

```powershell
.\wxclipd.exe --poll-interval 15 --no-paste-trigger config
.\wxclipd.exe stop
.\wxclipd.exe start
```

`--paste-trigger` 可重新开启触发。本地剪贴板默认每 400 毫秒检查一次；`--interval` 和 `--paste-trigger-debounce-ms` 是前台 `run` 参数，不写入 `config.json`。

便携版默认也使用 `%LOCALAPPDATA%\wxclipd`，不会把身份和日志放到程序旁边。需要独立目录时，所有命令使用相同的 `--state`，例如：

```powershell
.\wxclipd.exe --state "D:\WeTypeData" setup
.\wxclipd.exe --state "D:\WeTypeData" stop
.\wxclipd.exe --state "D:\WeTypeData" start
```

也可以设置 `WXCLIPD_STATE`，显式 `--state` 的优先级更高。同一状态目录只能运行一个同步进程。

状态目录包含设备身份、私钥、账号 secret、接收记录，以及可能带密码的代理 URL，均以明文存储；程序通过 Windows ACL 将目录访问限制为当前用户和系统。不要分享整个目录。卸载会停止同步并删除安装文件、自启项，**保留状态目录和配对身份**。

## 配对、重试与常见问题

**如何查看设备、添加配对或解绑？**

```powershell
.\wxclipd.exe devices
.\wxclipd.exe pair 123456
.\wxclipd.exe unbind --peer UIN
```

`pair` 后在手机确认；只有一个可解绑设备时可省略 `--peer`。若让电脑显示六位码，先 `stop`，再运行 `.\wxclipd.exe code`，在手机输入该码，结束后重新 `start`。

**手机复制后电脑还没有更新。**

先确认手机和电脑已配对，检查日志中的网络或代理错误，等待一次远端轮询，或运行 `.\wxclipd.exe sync-now` 请求同步。Ctrl / 右键触发会提前拉取，但网络请求可能晚于粘贴操作完成。修改代理后要重启；如果配置显示的代理与文件不同，检查 `WXCLIPD_PROXY`。

**断网时复制的内容如何处理？**

临时网络故障会退避重试。出站只在内存中保存最新待发送的文本或图片，后续复制会替代旧内容；退出或重启会丢失待发状态。入站内容先持久化，剪贴板暂时被占用时保留并重试；此时用户新复制的本地内容优先。

如果日志显示 **`OutcomeUnknown` / 发送结果不确定**，服务端可能已收到该内容，程序暂停自动重发。需要重试时执行 `.\wxclipd.exe sync-now`，这可能重复发送；也可复制新内容继续同步。

**日志反复出现 `control HTTP status 400`。**

0.4.2 修复了旧版将发布前的控制 HTTP 400 当作不可自动重试错误、持续拉取失败却不重建会话的问题。程序会清除被拒绝的控制会话密钥；可安全重试的控制请求重新校准时间、协商密钥后重试一次。若重建失败，后续请求仍会继续尝试恢复，保留配对身份与代理设置。

在最终发布前遇到该错误时，最新待发文本或图片会保留，按约 1、2、4、8、16、30 秒退避，之后每隔约 30 秒继续尝试；无需反复点「立即同步」。这些是重试等待时间，请求耗时另计。期间复制新内容会替代原待发内容。持续 400 不一定是会话失效；若一直无法恢复，请检查代理和日志，反馈版本号及错误行。

`COS HTTP status 400` 属于对象传输错误，不按控制会话故障自动恢复。如果最终发布请求的结果无法确认，仍按上面的「发送结果不确定」处理，避免自动重复发送。

**哪些内容会同步？**

非空文本（最多 **1 MiB，按 UTF-8 字节**）和上述 PNG / JPEG / Windows 位图内容。程序默认不会上传启动前已有的剪贴板；首次验证请复制新文本或图片。若确实要发送启动前内容，停止后台后前台运行 `.\wxclipd.exe --send-current run`。

**图片没同步，文本正常。**

图片没同步而文本正常时，确认复制的是图片内容而非文件，先用一张较小的 PNG 截图重试；接收端使用支持图片粘贴的应用。查看日志是否有大小限制、格式、解码、COS 上传或代理错误。图片传输时间通常比文本长，等待后可请求一次 `sync-now`。持续失败时请反馈版本号、格式/尺寸及隐藏凭据后的错误行，不要上传配对状态目录或私密图片。

**如何核对下载文件？**

发布页同时提供 `SHA256SUMS.txt`。PowerShell 可计算下载文件的校验值，与对应行比较：

```powershell
Get-FileHash .\wetype-clipboard-sync-0.5.0-windows-x86-setup.exe -Algorithm SHA256
```
