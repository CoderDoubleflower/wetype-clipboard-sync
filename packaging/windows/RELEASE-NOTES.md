## v0.4.2 · HTTP 400 后自动恢复同步

本版修复后台遇到 `control HTTP status 400` 后上传暂停、拉取反复失败却不恢复会话的问题。继续提供 **Windows 10 及以上、32 位 x86** 安装包与便携版，可在 64 位 Windows 上运行。

### 下载

- `wetype-clipboard-sync-0.4.2-windows-x86-setup.exe`：当前用户安装，可选登录自启。
- `wetype-clipboard-sync-0.4.2-windows-x86-portable.zip`：完整解压后双击 `wxclipd-background.exe`，两个 EXE 须放在同一目录。
- `SHA256SUMS.txt`：上述文件的 SHA-256 校验值。

### 本版修复

- **自动恢复控制会话**：收到控制 HTTP 400 时清除当前控制密钥；可安全重试的控制请求重新校准服务端时间、执行 ECDH，再重试一次。持续失败会返回上层退避，避免在一次请求内无限重建。
- **失败后仍能继续恢复**：会话初始化失败或被中断后，后续请求会重新初始化，不再卡在 `session not initialized`。
- **保留最新待发内容**：最终发布前的控制 HTTP 400 不再暂停自动发送。待发文本或图片按约 1、2、4、8、16、30 秒退避，之后每隔约 30 秒继续尝试；请求耗时另计。新复制内容会替代原待发内容，无需反复点击「立即同步」。
- **保留发布结果保护**：最终发布请求结果不确定时仍暂停自动重发，避免重复发送；可用「立即同步」或复制新内容继续。COS HTTP 400 不作为控制会话错误处理。
- **升级验收更新**：以已发布并校验 SHA-256 的 0.4.1 安装包为基准，验证运行中的旧托盘和同步进程能够关闭，并保留身份与配置。

仅凭 HTTP 400 无法确定服务端拒绝的具体原因；本版补齐客户端的恢复路径。双向文本 / 图片、HTTP / SOCKS5 代理、微信输入法图标、托盘与状态配置窗口继续保留，恢复过程使用原配对身份和代理设置。

### 升级与使用

已安装 0.2.0、0.3.0、0.4.0 或 0.4.1 时，直接运行新安装包覆盖安装。安装器会停止旧进程，保留配对身份和代理设置，已有设备无需重新配对。设置向导若仍在运行，请先完成并关闭。便携版先停止同步、退出托盘，再完整解压新版覆盖文件。

启动后可双击右下角微信输入法图标查看状态；图标可能在 `^` 隐藏区域。升级会重启进程，旧进程内存中的待发内容不会迁移，首次验证请重新复制一段文本或图片。

详细操作及错误说明见包内文档与 [Windows 指南](https://github.com/CoderDoubleflower/wetype-clipboard-sync/blob/v0.4.2/packaging/windows/README-Windows.md)。

### 发布验证

发布流程要求 Windows 应用与协议测试、控制会话恢复回归测试、原生图片剪贴板、本地代理传图、x86 构建、图标资源检查，以及安装 / 托盘 / 单实例 / 停止 / 重启 / 退出 / 卸载验证通过后才发布。

Windows CI 在 x64 Windows Server 2022 上运行 x86 程序。自动验证使用本地模拟服务，不连接真实手机账号；实际服务端与已配对手机上的长期恢复仍需实际使用确认。

本项目与腾讯无关联，微信输入法图标权利归原权利人，官方协议更新可能影响兼容性。安装包未做商业代码签名。
